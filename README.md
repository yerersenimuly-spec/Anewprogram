# Line 0.8.0

Мессенджер Android со сквозным шифрованием (libsignal PQXDH + Double Ratchet) и групповыми E2EE-звонками через собственный LiveKit SFU. Сервер — однопроцессный Node.js: хранит только ciphertext, публичные ключи и хеши токенов, приватных ключей и plaintext не содержит.

## Что нового в 0.8.0

- **Надёжность и offline-first:** durable-очередь зашифрованных сообщений на сервере (до 7 суток, до подтверждения получателем), outbox на устройстве повторяет тот же ciphertext при переподключении, автоматическое восстановление соединения.
- **Статусы сообщений:** Отправлено / Доставлено / Прочитано. Квитанции о прочтении идут silent-конвертами, которые никогда не вызывают push.
- **Полная переработка интерфейса (UI/UX):** новая дизайн-система, экраны звонков, чатов, переписки и профиля; премиум-итог после звонка; звуки интерфейса отделены от уведомлений.
- **Отображаемые имена:** профили (`profile_set`/`profile_get`), имя видно в чатах, приглашениях и пропущенных звонках.
- **Голосовые сообщения и медиавложения (E2EE):** запись и воспроизведение голоса, вложения до 26 MiB; шифрование на устройстве, сервер хранит только ciphertext по одноразовым билетам.
- **Push без Firebase:** UnifiedPush с шифрованием RFC 8291 и защитой от SSRF; опционально APNs. Firebase убран, старые FCM-токены игнорируются. Настройка — [docs/PUSH-SETUP.md](docs/PUSH-SETUP.md) (self-hosted ntfy).
- **Пропущенные звонки** с подтверждением (`missed_ack`) и **возврат в звонок**: у клиента v8 есть grace-окно (15 с по умолчанию) на переподключение без разрыва медиасессии.
- **API v8** с полной обратной совместимостью: клиенты 0.7.x (протоколы 6–7) работают с сервером 0.8 без изменений.

## Ограничения

- Сквозные проверки на физических устройствах не проводились: звонки между реальными телефонами, доставка push через реальный distributor и iOS/APNs не проверены; APNs-ветка покрыта только тестами с injectable-коннектором.
- Push после force stop гарантировать нельзя: ограничения ОС и производителей.
- APK этой среды подписан debug-ключом и не устанавливается поверх ранее выпущенных сборок; для обновления без потери данных нужен исходный ключ владельца (`LINE_KEYSTORE`). Не удаляйте приложение и не очищайте данные ради установки.
- Независимый аудит не выполнен; сервер и SFU видят номера, IP, состав и время. Key transparency, sealed sender и скрытие метаданных не реализованы.

## Обновление VPS

Код сервера и файлы данных/ключей не изменяются на месте — обновление неразрушающее: бэкап → read-only проверка `check-data-compat` на **копии** данных → новый каталог кода с `npm ci --omit=dev` → перезапуск. Существующие файлы данных никогда не переписываются в новый формат, новые хранилища создаются в отдельных файлах. Откат — вернуть прежний каталог кода, данные не трогаются. Пошагово: [docs/API.md](docs/API.md), раздел 9, и [server/README.md](server/README.md).

## Сборка

Java **21**, Kotlin **2.2.20**, Android SDK 36, Node 24. APK: `versionCode 9`, `versionName 0.8.0`; release подписывается `LINE_KEYSTORE`, иначе debug-ключом. Debug-варианты по ABI: `app-arm64-v8a-debug.apk` и другие; для магазина — AAB. Секреты и ключи подписи в Git/APK не включать.


## Настоящие серверы

Развёртывание — [deploy/README.md](deploy/README.md) и [server/README.md](server/README.md): LiveKit с UDP/TCP ICE и TURN, API с `LIVEKIT_URL`/`LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET` и TLS reverse proxy. Для push нужен свой ntfy-сервер ([docs/PUSH-SETUP.md](docs/PUSH-SETUP.md)); Firebase больше не требуется. На телефонах — API `wss://api.ваш-домен/signal`, LiveKit `wss://rtc.ваш-домен` и SHA-256 SPKI pins обоих сертификатов из доверенного источника; резервный pin через запятую позволяет ротацию, неверный pin блокирует подключение. Для другого API-сервера нужен новый профиль: номер и доверие не переносятся.

## Пользоваться

1. После регистрации появится восьмизначный номер.
2. **Оба** абонента сверяют Signal safety number/SAS по доверенному каналу и подтверждают; подмена identity блокируется. Подтверждать код через сообщения того же сервера нельзя.
3. Сообщения шифруются (SQLite-WAL, AES-GCM/Keystore); история пагинируется локально. Сервер держит зашифрованную очередь offline-сообщений до подтверждения получателем; «Доставлено» — после `delivery_ack`, «Прочитано» — после квитанции получателя.
4. Вложения и голосовые отправляются в чате; сервер хранит только ciphertext до `blob_ack`.
5. В «Звонки» — до семи номеров через запятую; участники заранее сверяют SAS друг друга. У клиента v8 есть короткое окно возврата в звонок после потери сети.

HQ — потолок 510 Кбит/с Opus, DTX выключен; речевой режим 64 Кбит/с с DTX. Активный звонок использует microphone foreground service. Force stop, выключение телефона и ограничения производителя могут остановить сервис и push.

## Безопасность и статус

Сервер хранит token hash, публичные bundles и Signal-ciphertext очереди/почтового ящика; метаданные (кто, кому, когда) остаются видимыми серверу, SFU и операторам сети. Не реализованы key transparency, sealed sender, защита от compromised/root телефона или записи собеседником.

libsignal — upstream-библиотека, не официальный Signal-клиент; использование вне Signal не поддерживается. **AGPL-3.0**: при передаче APK предоставляйте соответствующие исходники; см. `LICENSE`.
