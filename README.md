# Line 0.7.1 — Android: звонки и Чат

## Совместимость с существующим сервером 0.6

0.7.1 исправляет ошибку входа на неизменённый API 0.6. Новый клиент сначала передаёт `protocolVersion: 7`; если старый строгий сервер отвечает `registration_required`, приложение **один раз** повторяет регистрацию пакетом `type/token/bundle`. Installation token, Signal identity, TLS pins и номер не меняются. Неверный token/bundle, блокировка или отказ регистрации не вызывают fallback. После успешного входа протокол не понижается.

На сервере 0.6 работают прежние онлайн-звонки/чат, но команды доставки v7 (`delivery_ack`, `inbox_sync`, `push_register`) не отправляются. Push и durable mailbox требуют обновления API; это прямо указано в экране подключения. Существующие адреса, сертификаты, коды подключения и данные пользователя не нужно менять или очищать.

Новый APK имеет `versionCode 8`, `versionName 0.7.1` и ту же подпись, что выданная здесь 0.7.0: его можно установить поверх **0.7.0**. Подпись исходной 0.6 из другой среды по-прежнему отличается — для update поверх неё нужен прежний signing key; uninstall/очистка данных не предлагаются как обход.

## Исправления 0.7

Основа — присланный владельцем архив завершённой 0.6.0, а не незавершённая промежуточная копия. Найден и исправлен дефект первой входящей Signal-доставки: код требовал готовую сессию до обработки PreKey-пакета, создающего эту сессию. Для PreKey теперь требуется подтверждённая identity/SAS, но не готовая сессия; подпись и совпадение identity проверяются как раньше. Обычные ratchet-сообщения по-прежнему требуют сессию.

Новый сервер сохраняет только ciphertext в ограниченной durable очереди до подтверждения получателем (TTL 7 дней). `queued` не означает доставку; `delivered` отправляется после клиентского `delivery_ack`. Непроверенный контакт не приводит к потере сообщения: пакет остаётся в очереди, повторяется после проверки контакта. Требуется обновить **API-сервер и оба клиента** для протокола 7. Старые клиенты совместимы на переходный период, но не дают новых гарантий подтверждения.

«Сообщения» переименованы в **Чат / Chat / Чат**. Профиль обновлён, подключение имеет отдельную карточку состояния и безопасную проверку/смену кода без сброса identity. Уведомления показывают только входящие события; исходящие звонки остаются в «Недавних», собственные отправки — в чате. Резкий синтезированный beep заменён тихим системным кликом; звук интерфейса по умолчанию выключен.

FCM/WorkManager реализованы, но **не активированы без Firebase-конфигурации владельца**. Администратор может импортировать публичный `google-services.json`; приватный service-account JSON принимается только сервером, не приложением. Настройка: [docs/ANDROID-PUSH.md](docs/ANDROID-PUSH.md), [docs/PUSH-SETUP.md](docs/PUSH-SETUP.md). FCM передаёт только тип события/UUID, не текст и ключи; worker подключается к pinned WSS и обрабатывает ciphertext. Force-stop и ограничения ОС исключают абсолютную гарантию push.

**Подпись APK:** присланный владельцем 0.6.0 подписан другим ключом. Новый debug APK этой среды не устанавливается поверх него. Не удаляйте приложение, не очищайте данные/ключи ради установки. Для обновления без потери истории новый APK должен быть подписан исходным ключом в прежней среде владельца; приватный ключ не присылайте в чат. Исходники 0.7 предоставлены для такой сборки.

## Интерфейс 0.6

Русский, English и Қазақша выбираются в профиле; выбор сохраняется на устройстве. Статус подключения и отсутствие назначенного номера показаны только в профиле. В сообщениях есть поиск по всей локальной зашифрованной истории и поиск внутри диалога. Удалённые сообщения исключаются из поиска. В звонках добавлена вкладка «Недавние»; результаты завершённых, отменённых, отклонённых и пропущенных звонков сохраняются локально. Короткий вызов до соединения не считается состоявшимся разговором; намерение отправить «маяк» определить нельзя.

Раздел «Уведомления» в профиле показывает события сообщений и результаты звонков, без содержимого переписки. Журнал шифруется в существующей SQLite/Keystore и ограничен 300 событиями. Есть отдельные переключатели звука отправки и нажатий. Звуки входящих и разрешения на уведомления управляются Android. Системные уведомления не показывают текст сообщений; нажатие открывает диалог или звонки.

**Ограничение не изменилось:** новые входящие звонки и сообщения принимаются только при работающем подключённом приложении. Push/FCM и гарантированный приём после закрытия приложения не добавлены. Звук на физическом устройстве и публичные звонки необходимо проверять отдельно. Сборка — debug, не production-релиз; для обновления ранее установленного APK нужен тот же ключ подписи. Не удаляйте данные приложения ради обхода несовпадения подписи: это уничтожит локальные ключи, историю и регистрацию.

## Администратор и удаление

Админ-раздел не показывается в обычном профиле. Три нажатия вкладки «Профиль» за 1,8 секунды открывают ввод серверного секрета. В APK нет универсального пароля: администратор задаёт scrypt-хеш через `ADMIN_PASSWORD_HASH`. Требуются зарегистрированное подключение с закреплённым TLS и правильный код. Сессия привязана к WebSocket, действует до пяти минут и закрывается при сворачивании, выходе или истечении срока.

Работающие серверные действия: разрешить/запретить звонки, сообщения и новые аккаунты, лимит группы 2–8, блокировка/разблокировка аккаунта и завершение активного звонка. Правила/блокировки сохраняются в `ADMIN_DATA_FILE` с правами `0600`; обычный клиент не может их изменить. Метрики и журнал доступны после входа. Журнал последних 100 событий в памяти содержит только фиксированные тип события, время и результат — без текста чата, аудио, ключей, IP или номеров участников. Экспорт диагностики и кода подключения работает через буфер обмена.

Долгое нажатие на сообщение → «Удалить на этом устройстве»; меню контакта → очистка локальной переписки. Копия у собеседника остаётся. Текст заменяется зашифрованным пустым значением; идентификатор-tombstone сохраняется против повторного восстановления. Очередь выбранного диалога очищается, ratchet/identity/trust не сбрасываются. SQLite версии 1 мигрирует на 2 без смены ключей.

**Где взять сервис и как запустить:** [русская пошаговая инструкция](docs/SERVICE-SETUP-RU.md). Для начала нужны VPS Ubuntu 24.04 с публичным IPv4, ориентировочно 2 vCPU/4 GiB, и домен. Подойдут Hetzner/DigitalOcean или другой VPS с UDP; стоимость и доступность проверяйте у провайдера. VPS/домен в этой задаче не покупались, публичный сервис не развёрнут.

Проверки 0.5: Android Lint/сборка, 18 JVM-тестов, 19 серверных тестов, семь локальных Android-проверок и отдельный сквозной admin-тест. Через настоящий pinned local WSS сервер проверил код, UI-переключатели изменили реальные серверные правила, а выход запретил дальнейшие команды. `scripts/test-android-admin.sh` воспроизводит этот тест на подключённом x86_64 Android-эмуляторе; временный TLS trust действует только для localhost/debug и удаляется после теста. Перед выдачей APK выполните обычный `assembleDebug`, чтобы исключить тестовый сертификат. Это не проверка публичного DNS/TURN или живого группового аудиозвонка.

## Новый интерфейс

Три экрана: звонки, сообщения, профиль. С основных экранов убраны технические названия и слоганы; поля подключения не содержат фиктивных адресов. Если сервис ещё не подключён, карточка объясняет, почему номер отсутствует. После регистрации серверный номер виден и сохраняется при потере связи. Сервер сообщает `mediaReady`: наличие настроек LiveKit, не доказательство доступности SFU по сети; чат и готовность звонков отображаются отдельно.

Переходы используют alpha/translation и небольшой scale через ViewPropertyAnimator, без анимации размеров/layout и вечных циклов. Системное отключение анимаций учитывается. Политика дисплея запрашивает только поддерживаемую бесшовную частоту текущего разрешения до 120 Гц. Это предпочтение, а не гарантия 120 FPS: энергосбережение, нагрев, дисплей и Android могут ограничить частоту. Пагинация истории, DiffUtil и SQLite/криптография вне UI-потока сохранены.

Для обычного пользователя подключение — один код `LINE1.…` от доверенного администратора. В профиле есть ручные настройки для администратора, отдельно от основных экранов. Создать код после развёртывания реальных серверов:

```sh
node scripts/connection-code.mjs \
  --api 'wss://api.ВАШ-ДОМЕН/signal' --api-pin 'sha256/НАСТОЯЩИЙ-PIN' \
  --media 'wss://rtc.ВАШ-ДОМЕН' --media-pin 'sha256/НАСТОЯЩИЙ-PIN' \
  --output connection-code.txt
```

Код содержит публичные адреса/pins, не секрет LiveKit. Проверка TLS/SAS не отключается ради удобства. Без реального сервиса серверный номер не может появиться; приложение не рисует фальшивый номер.

Нативный Kotlin, Android 8+, чёрно-белый интерфейс. **LiveKit SFU** для фиксированных групп из 2–8 человек, **Opus**, нативное E2EE (frame cryptor); **libsignal PQXDH + Double Ratchet** для сообщений и передачи ключа комнаты. WebSocket relay, локальная SQLite с AES-GCM/Android Keystore, постраничная история и RecyclerView.

**Это тестовая сборка, не готовая публичная служба связи.** Без доступных API/LiveKit/TURN-серверов один APK не обеспечивает реальные звонки. Серверы в этом задании не развёрнуты. Полная неотслеживаемость и отсутствие любых задержек невозможны: E2EE скрывает содержимое, но инфраструктура и сеть видят IP, номера/участников и время соединения. Независимый аудит не выполнен.

## Архитектура и код

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — архитектура, модель доверия, структура и пример LiveKit E2EE для SDK **2.29.0**. Android использует native frame encryption, не браузерный JavaScript Insertable Streams API.

```
app/src/main/java/app/line/
  MainActivity.kt       # Звонки, Signal safety numbers, RecyclerView-чат
  CallService.kt        # Фон, fixed roster, Signal-ключ комнаты, потеря сети
  EndpointConfig.kt     # WSS + SPKI certificate pins API и LiveKit
  media/                # LiveKit E2EE, Opus HQ/речь, микрофон и динамик
  crypto/               # libsignal, SQLite, Keystore, ciphertext outbox
server/                 # Учёт установки, публичные prekeys, relay, LiveKit JWT
deploy/                 # LiveKit/embedded TURN/Caddy шаблоны и ports
```

Identity/prekeys и случайный 32-байтовый room key генерируются **только на телефоне**. Инициатор передаёт room key через проверенные Signal-сессии. JWT действует 120 секунд, связан с комнатой/участником, разрешает публикацию только микрофона. При выходе/отключении любого участника вся группа завершается; новый состав требует нового звонка/ключа. Live-добавления и live-ротации ключей нет.

## Сборка

Java **21**, Node **24**, Kotlin **2.2.20**, SDK Android **36**, NDK **28.2.13676358**. libsignal 0.104.0 требует JDK 21; desugaring сохраняет поддержку старых Android.

```sh
mise use java@temurin-21
bash scripts/setup.sh
./gradlew assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug
npm test
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

В Android Studio откройте корень. Setup принимает лицензии SDK и создаёт `local.properties`. Debug APK — для проверки; для публикации нужны release-подпись, испытания и аудит. APK не содержит testing JNI; NDK убирает debug symbols. Для меньшего скачивания доступны `app-arm64-v8a-debug.apk` (большинство современных телефонов), `app-armeabi-v7a-debug.apk` (32-битные ARM), x86/x86_64 и универсальный APK. Для магазина используйте AAB. Секреты и signing/private keys нельзя включать в Git/APK.

## Настоящие серверы

См. [deploy/README.md](deploy/README.md) и [server/README.md](server/README.md): разверните LiveKit с UDP/TCP ICE и TURN, API с `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` и TLS reverse proxy. Без media config выдача токена отказывает, fake token не используется.

На телефонах введите API `wss://api.ваш-домен/signal`, LiveKit `wss://rtc.ваш-домен` и **SHA-256 SPKI pins** обоих сертификатов из доверенного источника. Например на администрируемом хосте:

```sh
openssl x509 -in fullchain.pem -pubkey -noout \
  | openssl pkey -pubin -outform DER \
  | openssl dgst -sha256 -binary | openssl base64 -A
# В приложение: sha256/РЕЗУЛЬТАТ. Это публичный pin, не приватный ключ.
```

Резервный pin через запятую позволяет ротацию. При неверном pin подключение блокируется. Для другого API-сервера нужен новый профиль/очистка данных: номер и доверие не переносятся.

## Пользоваться

1. После регистрации появится восьмизначный номер; поделитесь им с другом.
2. **Оба** открывают номера друг друга в «Чат», сверяют **весь Signal safety number/SAS** лично или через иной доверенный канал и подтверждают совпадение. Подмена identity блокируется. Нельзя подтверждать код только по сообщению через тот же потенциально атакуемый сервер.
3. Отправляйте сообщения. SQLite-WAL шифрует тексты/ratchet/outbox AES-GCM с Keystore. История — индексированный keyset `LIMIT 40` (максимум 100 в API), отображаемое окно до 200 сообщений.
4. В «Звонки» укажите до семи номеров через запятую. Все участники заранее должны сверить SAS остальных. Приглашённые нажимают «Ответить».

HQ — потолок **510 Кбит/с Opus**, DTX выключен; речевой режим — 64 Кбит/с с DTX. Максимальный битрейт не гарантирует лучшее качество в слабой сети и не устраняет физическую задержку. SDK адаптируется к полосе.

Активный звонок использует microphone foreground service/уведомление/wake lock. Потеря интернета или signaling/media завершает звонок, без бесконечного reconnect медиакомнаты. **Новые входящие — при открытом приложении**; FCM/Telecom не реализованы. Force stop, выключение телефона и ограничения производителя могут остановить сервис.

Сервер не хранит offline-сообщения. Локальный encrypted outbox повторяет тот же ciphertext при переподключении отправителя. «Отправлено» — передача в подключённый WebSocket, **не расшифровка/прочтение**. До SAS входящие отклоняются. Attachments, multi-device sync и push отсутствуют.

## Безопасность и статус

Сервер хранит token hash/публичные bundles, маршрутизирует ciphertext и не содержит приватные ключи/не пишет plaintext или аудио. SFU всё равно знает состав/IP/время. Не реализованы key transparency, sealed sender, скрытие метаданных, защита от compromised/root телефона, записи собеседником или глобального анализа трафика.

libsignal — upstream-библиотека, не официальный Signal-клиент; использование вне Signal не поддерживается. **AGPL-3.0**: при передаче APK предоставляйте соответствующие исходники; см. `LICENSE`.

В версии 0.3 прошли 17 JVM-тестов, 10 тестов сервера, Android Lint и сборка APK. На AOSP Android 8.0 (API 26) успешно выполнены три инструментальных теста: импорт подключения, Android Keystore/зашифрованная SQLite с пагинацией и запуск/навигация UI. При этой проверке исправлена реальная ошибка открытия SQLite (`PRAGMA secure_delete` возвращает результат и требует query). Первый экран APK запущен и визуально проверен; автоматическое открытие клавиатуры устранено, основная кнопка закреплена внизу. Среда затем перезапустилась и утратила файлы снимков, поэтому они не выдаются как сохранённое доказательство.

LiveKit Server **1.13.7** запущен локально: создание, чтение и удаление комнаты с `maxParticipants=8` прошли. Локальный smoke-тест использовал loopback, без внешнего TURN/TLS; он не подтверждает слышимый аудиозвонок между телефонами. **Не проверены публичное развёртывание, реальный групповой звонок, фоновое аудио на физических телефонах и фактические 120 FPS.** Software-эмулятор не является устройством для измерения производительности. Подробный отчёт: [docs/VERIFICATION-0.3.md](docs/VERIFICATION-0.3.md). До production нужны несколько физических телефонов и независимый аудит.
