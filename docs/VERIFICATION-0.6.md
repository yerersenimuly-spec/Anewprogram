# Проверка Line 0.6.0

Дата: 3 октября 2026. Это проверка тестовой сборки, не независимый аудит безопасности.

## Подтверждено

- `./gradlew --no-daemon assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug` — успешно. Все 18 JVM-тестов прошли; Android Lint без ошибок. Предупреждения устаревших Android API остаются.
- `npm test` — 23 серверных теста прошли.
- AOSP Android 11, API 30, x86_64: 28 инструментальных тестов прошли. Классы запускались последовательно, с очисткой **тестовых** данных перед каждым классом, чтобы изолировать SQLite/Keystore и сервисные fixtures.

| Класс | Тесты |
| --- | ---: |
| ActivityJournalTest | 5 |
| CallServiceLifecycleTest | 4 |
| ConnectionProfileDeviceTest | 1 |
| LocalStoreTest | 1 |
| MessageDeletionTest | 6 |
| NotificationTest | 3 |
| UiFeaturesTest | 5 |
| UiFlowTest | 3 |

Проверены переключение ru/en/kk с пересозданием Activity, неизменность пользовательского текста, отсутствие статуса связи в шапке, единственная надпись о неназначенном номере в профиле, пустой inbox и поле «Имя (необязательно)», поиск старых сообщений и переход к найденному сообщению, исключение удалённых сообщений, недавние звонки и статусы, журнал уведомлений и переключатели звуков. Системные уведомления действительно публикуются; переход открывает нужный диалог, входящее уведомление заменяется пропущенным, приватная версия не содержит текста переписки.

История звонков сохраняется между открытиями хранилища, имеет уникальные курсоры и предел 300 событий. Метаданные участников и исходов зашифрованы. Ошибка соединённого звонка может сохраняться с длительностью. Проверены миграция старой схемы с сохранением identity, tombstones и атомарное подтверждение outbox.

При проверке исправлены неправильный разбор сериализованных EC prekeys, повторное стартовое подключение после смены конфигурации и закрытие ещё создающегося хранилища. Проверки SAS, подписей prekeys и TLS pins не отключались.

Свежие снимки получены с работающего Android. Любые имена и сообщения на них — fixtures из test APK, не данные пользователей и не содержимое выдаваемого приложения. Программный эмулятор работал без KVM и аудиовывода; для проверки использовались два виртуальных CPU, 2 GiB памяти, 720×1280 и плотность 320 dpi.

## Воспроизведение Android-проверок

После установки обычного debug APK и androidTest APK на **тестовый** эмулятор:

```sh
for test in ActivityJournalTest CallServiceLifecycleTest ConnectionProfileDeviceTest \
  LocalStoreTest MessageDeletionTest NotificationTest UiFeaturesTest UiFlowTest; do
  adb shell pm clear app.line
  adb shell am instrument -w -r -e class "app.line.$test" \
    app.line.test/androidx.test.runner.AndroidJUnitRunner
done
```

**Не выполняйте `pm clear` на личном телефоне с нужной регистрацией и историей.** Отдельный `AdminAccessTest` требует pinned local WSS fixture и запускается существующим `scripts/test-android-admin.sh`; в указанное число 28 он не включён. Серверные проверки админ-правил прошли.

## Ограничения

- Новые входящие по-прежнему принимаются при работающем подключённом приложении. Push/FCM и гарантированного приёма после его закрытия нет.
- Публичные API/LiveKit/TURN и реальный звонок между физическими телефонами здесь не проверялись. Слышимый звук отправки/нажатий, Bluetooth, фоновое аудио на телефоне и FPS не измерялись.
- Шифрование содержимого не скрывает IP, состав и время соединений от инфраструктуры.
- Выдаваемый APK — debug 0.6.0, versionCode 6, minSdk 26, targetSdk 36. Универсальная сборка содержит ARM64, ARMv7, x86 и x86_64; APK-подпись проверяется. Для обновления старого APK без удаления данных нужен прежний ключ подписи. Нельзя советовать удаление приложения как безвредный обход несовпадения подписи.
