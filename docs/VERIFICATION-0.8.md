# Line 0.8.0 — результат проверки

Дата: 2026-10-04. Релиз поверх медиаконвейера 0.7.x и переработки клиента: серверный протокол 8 (профили, квитанции, push без Firebase, пропущенные звонки, зашифрованные вложения), read-only инструмент проверки данных и документация. Настройки и данные действующего VPS не изменялись.

## Что реализовано

**Клиентское ядро** (`app/src/main/java/app/line/core/`, `push/`): статусы сообщений Отправлено/Доставлено/Прочитано, политика переподключения, offline-first outbox с повтором того же ciphertext, квитанции о доставке и прочтении, профили с отображаемыми именами, регистрация UnifiedPush, обработка push-уведомлений.

**Интерфейс** (`app/src/main/java/app/line/ui/` и `ui/screens/`): новая дизайн-система (тема, иконки, компоненты, sheets, motion) и экраны — онбординг, звонки, чаты, переписка, активный звонок, итог после звонка, профиль, админ-вход. Звуки интерфейса (`UiSounds`) отделены от уведомлений.

**Голосовые сообщения и вложения** (`media/attachments/`, `core/Attachment*`): запись голоса (VoiceRecorder/VoicePlayer, waveform) и передача медиавложений через AttachmentEngine; шифрование выполняется на устройстве (`AttachmentCrypto`), сервер хранит только ciphertext до подтверждения получателем (`blob_ack`).

**Сервер v8** (`server/src/index.js`, `push.js`, `blobs.js`): протокол 8 с переговорами и строгой совместимостью v6/v7; `profile_set`/`profile_get` (нормализация и фильтрация Unicode, лимиты); silent-конверты для квитанций о прочтении (доставляются как обычные, никогда не вызывают push); пропущенные звонки (`missed_call` после регистрации, до 20 записей на получателя и 7 суток, подтверждение `missed_ack`); возврат в звонок — grace-окно `CALL_RESUME_GRACE_MS` (по умолчанию 15 с, 0–60 с) с `call_resume` и новым `room_grant`; push через UnifiedPush (шифрование тела по RFC 8291 при наличии ключей, проверка endpoint на SSRF с повторной проверкой DNS и подключением ровно к проверенному адресу, склейка сообщений не чаще раза в 1500 мс) и опционально APNs; вложения — `blob_create`/`blob_get`/`blob_ack` с одноразовыми билетами на 10 минут, лимит 26 MiB по умолчанию. Firebase удалён: `firebase-admin` убран, `FCM_PROJECT_ID` и `GOOGLE_APPLICATION_CREDENTIALS` игнорируются без ошибок, старый файл FCM-токенов не читается и не изменяется.

**Совместимость данных:** существующие файлы (`identities`, `admin`, `mailbox`, `push.json`) никогда не переписываются в новый формат; новые хранилища (`profiles.json`, `push-endpoints.json`, `missed.json`, каталог blobs) создаются лениво при первой записи. `server/scripts/check-data-compat.mjs` — read-only проверка файлов теми же загрузчиками, что и сервер; `npm run check:data`.

**Release-сборка:** `debuggable` выключен, фильтр локалей; подпись — `LINE_KEYSTORE`, иначе debug-ключ.

## Ограничения

- **Нет E2E на физических устройствах:** голосовые звонки между реальными телефонами, доставка push через реальный distributor (например, self-hosted ntfy) и iOS не проверялись. Push-конвейер покрыт unit/серверными тестами с injectable-отправителем (включая RFC 8291-шифрование и SSRF-ветки), но живой доставки не было.
- **Force-stop по-прежнему нельзя разбудить:** push — подсказка «переподключись»; ОС и производители могут не запустить обработку после force stop. Гарантий доставки нет.
- **APNs не проверен без Apple-учётных данных:** серверная ветка покрыта тестами (регистрация, HTTP/2-коннектор инжектируется), живого соединения с Apple не было.
- **Подпись APK:** сборка этой среды подписана debug-ключом и не встанет поверх ранее установленных 0.6/0.7. Для обновления без потери данных нужен release-ключ владельца (`LINE_KEYSTORE`, `LINE_KEYSTORE_PASSWORD`, `LINE_KEY_PASSWORD`). Удалять приложение или очищать данные ради установки нельзя — это уничтожит локальные ключи и историю.
- Инструментальных Android-тестов нового UI в этом релизе не проводилось; редизайн подтверждён компиляцией, Lint и unit-тестами, но не скриншотами на устройстве.
- Независимый аудит, внешние TURN/TLS и нагрузочные испытания не выполнялись; SFU по-прежнему видит состав, IP и время.

## Обновление VPS (кратко)

Полная процедура — [`docs/API.md`](API.md), раздел 9. Порядок: бэкап каталога данных → `node scripts/check-data-compat.mjs` на **копии** данных (read-only) → распаковать релиз в новый каталог и `npm ci --omit=dev` → остановить сервис, поменять каталоги кода, запустить, проверить `/health`. Переменные окружения и старые файлы данных не меняются; новые файлы создаются рядом и только при первой записи. **Откат не требует восстановления данных**: старые файлы никогда не переписываются, 0.7.1 игнорирует новые файлы, а `push.json` не менялся — достаточно вернуть прежний каталог кода.
