# Line 0.7.1 — совместимость регистрации

Причина: APK 0.7.0 добавлял `protocolVersion: 7`, а неизменённый сервер 0.6 из присланного архива принимал только `type`, `token`, `bundle`. Сервер возвращал `registration_required`, клиент не входил и показывал общую ошибку.

Исправление: одна повторная регистрация теми же token/bundle в старом формате только после этого точного отказа до регистрации. Никакого отключения TLS pins, замены identity, сброса номера или пользовательских данных. Другие ошибки не приводят к fallback. После входа старому серверу не отправляются команды mailbox/FCM v7.

Проверки:

- точный `server/src/index.js` из вложенного окончательного 0.6 запущен локально: отклонил первый пакет и принял неизменённый старый пакет после повторения;
- unit-тесты проверяют один retry, сохранение token/bundle, отсутствие fallback на ошибках авторизации и после успешной регистрации;
- Android-тесты проверяют строгий старый WebSocket API: клиент входит, получает номер, отправляет онлайн-сообщение и не отправляет новые команды; новый API принимает один пакет v7 без повторения;
- сборка APK, instrumented test APK, JVM-тесты и Android Lint проверяются перед выдачей.

Это проверка локальной совместимости, не подключение к VPS владельца. Старый API не имеет server-side offline mailbox/push; поэтому 0.7.1 не обещает новые серверные функции на неизменённом сервере.

Подпись совпадает с APK 0.7.0 этой среды. Подпись присланного 0.6 отличается; данные телефона не очищались. В тестах `pm clear` использовался только на disposable эмуляторе.
